# gSpot status report: 15 Oct 2026

What it would take to start using gSpot properly, and how far the code is from what it's meant to do. Everything below comes from the code, the git history, the live site and the `gspot-data` repo. File:line references are to commit `24babbf`.

## Intended use (from the spec and the 9 Sep handover)

A golf app for one person (CSJ), used on the phone. You enter scores hole by hole on one scrolling VPAR-style card, and it works out a WHS Handicap Index under England Golf rules. It keeps your rounds and stats and syncs to the private repo `Stoff73/gspot-data`.

## Blockers, in order

### 1. Sync has never run
Nothing on the phone has ever reached GitHub, so all data sits in that one browser's localStorage. If Safari's site data gets cleared, it's gone.
- **To do:** create the fine-grained token (only `gspot-data`, Contents read/write). Then in the app go to Courses → Sync, paste the token and tap Sync now. The handover covers the steps (`handover/Sept/09/handover.md:48`).
- The code handles a `null` server file: `pull()` marks the device `pending` and the next push seeds it (`app.js:73`, `app.js:82`). That path has only been tested against a mock, never real GitHub (handover line 36).

### 2. The six back-filled rounds wouldn't count toward the Index
`gspot-import.json` holds six 18-hole rounds (15 May to 22 Aug 2026), generated by `import_rounds.py`. None of them has `diff`, `raw`, `ags` or `pts`:
- `record()` only keeps rounds with a `diff` (`app.js:92`), so if this file were imported none of the six would count, and you'd still have "No index yet".
- The rounds list would show `undefined pts` and `diff –` (`app.js:254-255`). The round view's Adj gross would be blank (`app.js:245`), and Stats "Avg points" would show `NaN` (`app.js:311`).
- Every round has `hadIndex: false` (`import_rounds.py:54`). In the app's own flow, rounds 4–6 would have had an Index and should be capped at net double bogey, not par+5.

Data issues to settle **before** fixing the import:
- **Tees:** the script always picks the first tee listed (`import_rounds.py:51-52`), and that's the back tee every time: Westerham White, Surrey National Blue, Royal Blackheath Purple, Wildernesse White, Poult Wood White. Which tees you actually played from has to be confirmed. The tee sets the Course Rating and Slope, which drive the differential.
- **15 May, Westerham:** the stored totals don't match the hole scores. `gross` is 96 but the holes add up to 98, and `putts` is 27 but the holes add up to 26. The card needs checking.
- To show why tees matter: running these rounds through `handicap.js` exactly as stored gives differentials of 22.8, 8.7, 19.9, 11.3, 20.3, 11.3. That makes an Index of **9.0**, against the course handicaps of 16–22 you played off on those cards. The 8.7 at Surrey National off Blue does most of the work. Don't trust that number until the tees are confirmed.
- `import_rounds.py:4` hardcodes `/Users/CSJ/Desktop/gSpot`, which no longer exists since the repo moved, so the script won't run as it stands.

**To do:** confirm the tees and the 15 May card, then have the script (or the app's import) calculate `ags/diff/raw/pts` using the same logic as `finishRound` (`app.js:222-231`). The other option is to type the six cards in through the app, oldest first.

## Code issues found while reading

- **The RapidAPI key will be synced.** `apiSearch` saves the key into `S.settings.apiKey` (`app.js:374`). `syncData()` sends all of `settings` to GitHub (`app.js:24`), and Export JSON dumps all of `S` (`app.js:405`). So on the first sync the key ends up in `gspot-data/state.json`, which goes against the handover's "key is not in any file" rule. The repo is private, so the risk is small. The fix is to keep the key in its own localStorage entry, the way the GitHub token already is (`app.js:21-23`).
- **Back-filling uses today's Index, not the Index on the round's date.** `hadIndex` comes from `currentIndex()` (`app.js:178`), and so do the 9-hole conversion (`app.js:226`) and the default Course Handicap. That's correct if old cards go in oldest first; out of order, the caps and 9-hole differentials come out wrong.
- **Saved rounds can't be edited, only deleted** (`app.js:248`). Fixing a typo means typing the round in again.
- **The default date is in UTC** (`today()`, `app.js:4`). Between midnight and 1am BST it fills in yesterday's date. The field can be edited, so this is minor.
- **PCC isn't clamped** to −1..+3 (`app.js:177`). The input's min/max don't stop a typed value.
- **Long-term limit:** sync reads `state.json` inline through the contents API, and GitHub stops returning inline content for files over 1 MB. At about 1.9 KB per round, that's roughly 500 rounds. Beyond that, `pull()` would see no data and treat the server as empty (`app.js:65`, `app.js:73`). Years away; noted here only.
